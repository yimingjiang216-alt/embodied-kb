# 精读笔记 · LingBot-VLA 2.0

> arXiv 2607.06403 · 乐动（Robbyant，lingbot-vla-v2 开源）· 2026-07 · v1 论文 "From Foundation to Application"

## 基本情况

- 路线：**VLA（产业落地派）**
- 一句话：LingBot-VLA 1.0 的升级——6 万小时数据 + MoE 动作专家 + 双查询蒸馏（深度老师+视频老师），把 VLA 从实验室推向真机部署
- 定位：四大开源 VLA（π0.5 / GR00T N1.7 / Wall-OSS 0.5 / LingBot 2.0）中唯一"产业公司 + 完整方法创新"的一个
- 三大升级：泛化（数据）、动作空间（全身自由度）、时序推理（预测性代理任务）

## 数据（60,000 小时）

- 机器人 50,000h（从 90,000h 筛出）：**20 种本体**——单臂/双臂/半人形/全人形（Unitree G1、Fourier GR-2 灵巧手 12DoF、KUAVO、Tienkung…），DoF 最高 32
- 第一人称人类视频 10,000h
- 筛选管线：jerk 三阶差分 + 速度/加速度 Z-score 剔抖动；URDF 投影回放 + 人工核对状态-视频对齐（比纯自动筛讲究）
- 动作空间统一：26+ 维（双臂+头+腰+底盘+灵巧手），相对位姿 + 6D 旋转（与 Wall-OSS 同款选择）

## 架构

**① MoE 动作专家（核心架构贡献）**
- MoE 层替换 action expert 的 FFN：1 个共享专家（通用先验）+ N 个路由专家（特化容量），每 token 激活 top-K
- **DeepSeek-V3 同款三件套**：sigmoid 路由（避免 softmax 竞争）+ **辅助损失无关的负载均衡**（路由偏置 b 修正，不改主目标）+ 细粒度专家
- Scaling 实验：同活跃参数量预算下 MoE 训练损失/验证误差全面低于 Dense——**容量分配更有效而非单纯堆参数**
- 为什么 MoE 对 VLA 特别有用：多本体预训练的动作表示被本体动力学/任务逻辑/场景三个因素纠缠，token 级稀疏路由让每个动作 token 按自身特征选专家

**② 双查询蒸馏（时序推理的注入方式）**
- 两个可学习查询 [Q_t, Q_{t+T}] 拼进视觉文本 token：Q_t 看当前，Q_{t+T} 预测 T（=动作块长度）之后的未来
- **深度老师**（LingBot-Depth）：几何监督，L1 对齐深度表示——"未来长什么样"的几何先验
- **视频老师**（自研 DINO-Video）：DINOv3 初始化 + 因果时间注意力 + 3D-RoPE，500 万视频剪辑上自蒸馏训练——运动感知的时序表示
- 两个蒸馏损失都作用在 query 状态上，不干扰动作生成主路
- 谱系位置：**这是 FDM"未来当老师"思想的另一个变体**——FDM 用未来帧监督动作特征，LingBot 用未来表示（深度+视频特征）蒸馏查询状态；都是"训练时注入未来、推理时不用生成"

## 结果

- GM-100 双臂 9 任务（通用混合训练设定）：Agilex 66.2/34.4 超 π0.5（59.1/32.2）和 GR00T N1.7（36.3/17.8）；Galaxea R1 Pro 34.6/15.6 同样领先
- 长程移动操作：冰箱分拣 ID 77.1/OOD 37.0 vs π0.5 65.3/30.3；灶台清洁 84.3/67.5
- 提升集中在"需要精确 grounding + 目标导向执行"的任务（取钥匙扣 100/100）——正好对应双查询蒸馏的注入点
- 诚实观察：进度分和成功率差距大（常卡在最后精确放置）；本体相关因素（运动学/相机视角/动作空间对齐）仍是挑战

## 谱系定位

- 两问：预测动作 +（训练时）未来表示；不生成视频——VLA + FDM 式未来老师
- 与 FDM：同题不同解——FDM 监督动作特征本身，LingBot 加独立查询再蒸馏（可能更稳，不直接搅动动作表示）
- 与 Wall-OSS：同月发布的两条中国路线——小鹏答"预训练产出什么"，乐动答"怎么扩到 20 本体"；MoE（容量分配）vs MoT（路由分解）是两种架构答案
- 刷榜生态位：FDM/LoopWAM/StellaVLA 的对比表常客，是被超越的强基线
